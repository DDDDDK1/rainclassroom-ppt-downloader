# 长江雨课堂 PPT 下载器 — 设计文档

> 日期：2026-08-03
> 状态：已确认
> 目标站点：`https://changjiang.yuketang.cn/v2/web/index`（长江雨课堂）
> 产物：油猴脚本 `rainclassroom-ppt-downloader.user.js`

## 一、背景与目标

用户希望通过油猴脚本便捷下载长江雨课堂中的 PPT 课件，脚本具备**增量检测**能力：首次扫描记录全部课程及课件，之后扫描只呈现新增内容。

参考文档：《油猴（Tampermonkey）脚本完整编写规范》《雨课堂PPT下载器思路可行性完整评估》（位于 `reference/`，已忽略不入库）。

### 已确认的需求决策

| 决策点 | 结论 |
|--------|------|
| 接口调研 | 尚未抓包，作为流程第 0 阶段进行 |
| 触发方式 | 手动按钮触发扫描（不自动后台遍历，防风控） |
| 图片流课件 | 通过雨课堂"打印课件"功能输出 PDF（CDP 全自动，回退半自动打印框），不手动拼图片 |
| 下载方式 | 逐个下载（初版不引入 JSZip 打包） |
| 使用范围 | 发布分享（Greasy Fork / GitHub） |

## 二、方案选择

**方案 A：调用内部接口 + 页面原生 fetch（已选）**

- 在页面上下文用 `fetch` 调用同域课程列表/课件列表接口；
- 同域请求天然携带登录 Cookie 与请求头，规避大部分接口鉴权问题；
- 存储用 `GM_setValue/GM_getValue`，跨域持久、发布友好；
- 无需 `@connect`，元数据简洁。

**弃用方案：**

- 方案 B（`GM_xmlhttpRequest` 跨域封装）：需 `@connect`、多一层封装，下载大文件转 Blob 繁琐。
- 方案 C（DOM 解析）：受页面结构变化影响大，发布后易失效；新课件未渲染则扫不到。

**风险回退（已通过）**：阶段 0 抓包已验证 **无动态加密签名**——`sign` 为课程详情接口返回的 `course_sign`（每课固定 token），脚本直接获取即可。接口链路全部打通，详见 `docs/apis.md`。

## 三、架构

单文件 `rainclassroom-ppt-downloader.user.js`，IIFE 包裹、严格模式。内部 6 个解耦组件：

```
入口 (init) → 注入悬浮按钮、监听 SPA 路由
UI 层（悬浮按钮 + 模态面板）→ 扫描器（增量判断）→ 网络层 Api（fetch 同域接口）
存储层 Store（GM 读写缓存）↔ 扫描器 / 下载器 / 打印模块
下载器 Downloader → 逐个触发下载（pdf/pptx 直链）
打印模块 Print → 写 rain_print → /web/print → CDP 全自动 / 半自动打印框
```

| 组件 | 职责 | 关键点 |
|------|------|--------|
| 入口 init | 注入悬浮按钮；SPA 路由保活（history.pushState 拦截 + 轮询） | `@run-at document-end` |
| 存储层 Store | `GM_getValue/GM_setValue` 读写缓存：`getAll() / updateCourse() / clear()` | 单个 STORE_KEY |
| 网络层 Api | 封装 `fetch`：课程列表、课件列表、分页遍历；统一超时/错误处理 | 同域自动带 cookie |
| 扫描器 Scanner | 拉课程 → 对比缓存 → 拉新增课件 → 筛选可下载 → 产出清单 | 请求间隔、逐课串行 |
| UI 层 | 悬浮按钮 + 模态面板：清单渲染、复选框、下载、状态提示 | 原生 HTML/CSS |
| 下载器 Downloader | 逐个触发下载（`<a download>` 或 window.open） | 不引 JSZip |
| 打印模块 Print | 图片流课件：调接口拿 slideList → 写 `localStorage.rain_print` → 打开 `/web/print` → CDP `Page.printToPDF` 全自动，回退 `window.print()` 半自动 | CDP 需 Chrome 调试模式启动 |

## 四、数据模型

```js
const STORE_KEY = 'rcppt_cache_v1';

{
  version: 1,
  courses: [
    {
      courseId: "课程唯一ID",
      courseName: "课程名称",
      resources: [
        {
          resourceId: "课件唯一ID",
          name: "课件文件名",
          type: "pdf" | "pptx" | "img",   // img = 分片图片流，无直链
          url: "https://...",              // 图片流为 null
          scanTime: 1722650000
        }
      ],
      scanTime: 1722650000
    }
  ]
}
```

- 增量判定的唯一键为 `courseId + resourceId`，绝不依赖名称判断（防重名误判）。
- 缓存读取时做 JSON 校验，损坏则自动重置为空缓存并提示。

## 五、核心流程

### 首次扫描（空缓存）

```
点击【扫描课件】
  → 拉取全部课程列表（处理分页）
  → 缓存无 courseId → 视为新增课程
  → 逐个拉取该课程课件列表
  → 识别类型，判断是否带直链
  → 产出新增课件清单 → 弹出面板展示
  → 同步写入本地缓存
```

### 增量扫描（缓存已有）

```
点击【扫描课件】
  → 拉取最新课程列表
  → 逐课对比：
     ├─ courseId 不在缓存 → 新增课程 → 全量拉取课件
     └─ courseId 已存在   → 拉取最新课件列表
          ├─ resourceId 不在缓存 → 新增课件 → 加入清单
          └─ 已存在 → 跳过
  → 无新增 → 面板显示"无新增课件"
  → 有新课件 → 弹出面板供选择
  → 同步更新缓存
```

### 下载流程

```
勾选 N 个课件 → 点击【下载选中】
  → 逐个处理：
     ├─ type=pdf/pptx 且有 url → 创建 <a download> 触发浏览器下载
     └─ type=img（图片流）→ 打印模块导出 PDF：
          ├─ 检测到 CDP（http://localhost:9222）→ Page.printToPDF 全自动生成 PDF 文件
          └─ 无 CDP → 打开 /web/print + window.print() 半自动（用户点"另存为PDF"）
  → 下载间隙延时 ~800ms（规避浏览器连续下载拦截 + 降风控）
```

### 防风控策略

| 策略 | 说明 |
|------|------|
| 手动触发 | 绝不自动后台遍历 |
| 请求间隔 | 课程间/课件列表间延时 500~1200ms |
| 逐课串行 | 课件列表按课程逐个拉取，不走并发 |
| 幂等写入 | 扫描完成后统一更新缓存，中途失败不污染已存数据 |

## 六、UI 设计

**悬浮按钮**：右下角固定定位，文字"📄 雨课堂PPT下载"；点击进入"扫描中…"禁用态并显示进度；注入前检查防重复实例。

**模态面板**：
- 标题区：脚本名 + 摘要（"发现 3 个新课件 / 来自 2 门课"）；
- 清单区：每行 = 复选框 + 课件名 + 所属课程 + 类型徽标（`PDF` 绿 / `PPTX` 蓝 / `图片流` 灰禁用）；
- 操作区：【全选/全不选】【下载选中】【重新扫描】【清空列表】【关闭】；
- 下载状态行内显示（下载中 / 成功 / 失败）；
- 底部合规提示："课件版权归授课教师所有，仅供个人学习使用，请勿传播"。

## 七、错误处理与容错

| 场景 | 处理 |
|------|------|
| 接口返回 401 | 提示"登录已失效，请重新登录后重试" |
| 接口限流 / 5xx | 延时 2s 重试，最多 3 次；仍失败则跳过并标注 |
| 课件无直链（图片流） | 标记 `img` 类型，走打印模块导出 PDF（CDP 全自动 / 半自动回退） |
| 接口地址失效 | 集中定义在 Api 组件顶部常量，单点修改 |
| 缓存数据损坏 | JSON 校验失败 → 重置空缓存并提示 |
| 面板重复打开 | 已存在则聚焦而非新建 |

## 八、合规与发布

- 元数据：`@name` / `@namespace`（GitHub 地址）/ `@version` / `@homepageURL` / `@updateURL`（raw.user.js）/ `@downloadURL`；
- `@match` 精准限定 `https://changjiang.yuketang.cn/*`；
- `@grant` 仅声明 `GM_setValue`、`GM_getValue`；不引入外部库（`@require` 为空）；
- 面板内合规提示 + README 使用说明。

| 阶段 | 内容 | 产出 | 依赖 |
|------|------|------|------|

| 3. UI + 下载 | 模态面板、清单渲染、勾选、逐个下载器 | 端到端可用初版 | 阶段 2 |

### 阶段验收标准

- 阶段 0 通过 = 拿到两个接口真实请求信息，确认直链或图片流区分；
- 阶段 2 通过 = 控制台首扫产出清单 → 二扫产出"无新增"；
- 阶段 3 通过 = 勾选 2 个以上课件逐个下载成功；
- 阶段 5 通过 = 测试清单 6 项全部通过。

### 风险回退

阶段 0 若发现接口带复杂签名加密 → 暂停，评估逆向签名或转方案 C（DOM 解析）。

## 十、测试清单

1. 首次运行（空缓存）完整扫描；
2. 再次运行无新课程 → 清单为空；
3. 新增一门课程 → 仅展示新课程课件；
4. 原有课程新增课件 → 只展示新增课件；
5. 图片流课件 → 打印模块导出 PDF 成功（CDP 全自动；无 CDP 回退半自动打印框）；
6. 多页课程列表 → 分页全部抓取。
